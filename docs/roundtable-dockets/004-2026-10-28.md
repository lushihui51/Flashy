# Roundtable docket 004: 2026-10-28

Canvas: https://claude.ai/artifact/TKWvF6VkNSjH3PXPuHtWGj

## Open questions

- Q1. How should the deck page's cards look on a wide screen, where today they fill a table of one column per field?
  - Reason: dense screens come after the phone screens are right.
  - Owner: /product-decide
  - Needed by: nothing
- Q3. Should a user's mastery also fade with the time since they last practiced, so that "ready now" stays honest?
  - Reason: a fading circle can feel like being told you're behind, which PDR 027 rules out. The product owner means to bring in a way of keeping mastery that follows how memory fades over time and can name when a card is due, which would reopen PDR 021's "changes only when they practice" and PDR 027's "nothing due".
  - Owner: /product-decide
  - Needed by: nothing
- Q11. Should a user choose which of a deck's fields count in its cards' mastery, so that a field they've stopped studying can stay on the cards without holding the circles down?
  - Reason: a card's mastery is over every field of its deck (PDR 021), so a field the user keeps but no longer studies keeps every card from reading ready. The word for a field that counts is still to be chosen, since "active" already names a practice that can still be continued.
  - Owner: /product-decide
  - Needed by: nothing
- Q14. How should `EmaStrategy` translate a field's state into readiness, in place of LCD1?
  - Reason: LCD1 is a stand-in that has not weighed how readiness is computed, and it reads a field asked only as a prompt as less ready than the user is to recall it, short of PDR 021's how likely the user is to recall a field now.
  - Owner: /code-decide
  - Needed by: nothing
- Q15. Should a practice of chosen cards look different in Practice from a practice of whole decks, so the user can tell one from the other?
  - Reason: PDR 026 makes a practice of chosen cards a practice like any other, so its row shows a name, decks and configurations just as a practice of whole decks does, and nothing tells the user it holds only some of the cards.
  - Owner: /product-decide
  - Needed by: nothing

- LCD1. `EmaStrategy`'s readiness of a side is its recency-weighted rating average with the prior removed, read with Good as full. For a side reviewed n times, the prior's share, 50 × 0.7ⁿ, is removed from the stored value, the rest is divided by 1 − 0.7ⁿ, then by Good's score, 67, and capped at 1. A field's readiness is the average of the sides it has been reviewed on; reviewed on neither, it is 0. It reads the stored state alone. Good's score as the full mark is a named constant in app/mastery/ema.py.
  - Facts: `EmaStrategy` blends each side toward the rating scores 0, 33, 67 and 100 with α 0.3 from a prior of 50. The answer side always blends at 0.3; the prompt side's weight grows with how many answers the prompt was shown with. A field always asked as a prompt has only a prompt side. ADR 083 has each strategy translate one field's state into readiness.
  - Rejected: the stored value divided by 100, where a steady Good never reads full and one Good from the prior reads 55%; a new recall-rate column, exact but costing a migration and a `FieldMasteryState` change, left to a later strategy; a retrievability that fades with time, which PDR 021 rules out and Q3 holds.
  - Becomes true: one Good fills a field never practiced, and Easy also reads full but cushions a later slip. A prompt side reads somewhat low, since the prior's share is known exactly only on the answer side, so a field asked only as a prompt reads less ready than the user is to recall it. No schema change and no rebuild.
- LCD2. A change in readiness is its value after minus its value before, sorted into LPD7's five kinds by bands in app/mastery/readiness.py. The change is after minus before in readiness, for a card and for each field, under the before and after of `_compute_field_mastery_deltas` in app/services/practice_run.py, a field never reviewed counting 0. The bands are LPD7's 80, 55, 45 and 20, on its scale where 50 is no change, read as changes in readiness: +0.6 and above, up a lot; +0.1 up to +0.6, up; between −0.1 and +0.1, no change; −0.6 down to −0.1, down; below −0.6, down a lot. The breakdown returns each card's and each field's kind of change, and the signed change. The frontend counts and orders, and never compares against a band.
  - Facts: LPD7 sets its bands on a scale from 0 to 100 where 50 is no change, and leaves the placement to the code side. Readiness runs from 0 to 1 under every strategy, and all mastery arithmetic sits under app/mastery/ (ADR 083). The breakdown returns kinds of change, and the client classifies nothing (ADR 084).
  - Rejected: the change measured against the room a card had, which makes the badge mostly say where the card started; the bands in the frontend, which puts mastery arithmetic outside app/mastery/.
  - Becomes true: "Gains" and "Drops" order by the signed change, and PDR 024's counts are counts of the returned kinds.

The canvas draws each of these marks as one SVG. LPD1 makes the canvas hold for exact shapes. ADR 080 governs icons as pictures, and a mark drawn as part of a circle is not one.
  - Rejected: CSS circles with marks positioned inside; CSS sizes chosen to land on whole pixels, which breaks silently when an ancestor lands on a fraction; lucide's chevrons nested in the badge, whose geometry differs from the canvas.
  - Becomes true: a mark cannot drift from its circle. ADR 080 stays as written.
  - Drawings: 16, 17
- LCD4. A completed practice's time on Home is the time of its last rating.   - Facts: `practice_run` carries `created_at` only. `get_current_practice_card` marks a run completed on a read when no card is pending, for a finished run and a stranded one alike (ADR 073). `PracticeRunPage` refetches the run's state after every rating, so a finished run completes straight after its last rating.   - Rejected: a `completed_at` column stamped when the run completes, which stamps an old stranded run now and lifts its decks to the top; a stamp by the rating that leaves nothing pending, which still needs the last-rating rule for stranded runs; `created_at`, which sorts a practice finished today by the day it started.
  - Becomes true: PDR 016's order needs no schema change.

  - Facts: `GET /api/subjects`, `/api/decks`, `/api/deck_practice_configs` and `/api/practice_runs` each return a whole collection. `PracticeRunSummary` carries no progress; only each run's `GET .../state` does. No read says whether the user has any card.
  - Rejected: Home combining the existing lists, which fetches four collections for five yeses and noes plus one state read per active practice; progress on `PracticeRunSummary`, which makes every row on the Practice page pay for what only Home shows.
  - Becomes true: Home costs one request, and a write elsewhere shows on Home's next visit without invalidating `['home']`.
- LCD6. The row's "<" shows exactly when `useLocation().key !== "default"`, and tapping it calls `navigate(-1)`. It lives in frontend/src/components/ui/Breadcrumb.tsx, as a button spoken "Back" (LPD4).
