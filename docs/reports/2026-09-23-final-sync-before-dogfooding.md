## Deferred (each needs a decision)

1. **A practice can start on a deck with no cards.** `app/services/practice_run.py:218-286` (`start_practice_run`) validates each configuration and never checks how many practice cards `_snapshot_and_generate_deck` produced; `frontend/src/pages/PracticeCreatePage.tsx` has no guard either. Verified with a throwaway test (not kept): `POST /api/practice_runs` on a zero-card deck returns 201 with an active run, and `GET .../state` returns `session_status: completed` with `total_cards: 0` because `get_current_practice_card` completes it lazily. This contradicts task 004's carried invariant 2 ("no cardless session") and the comment at `app/services/deck_practice_config.py:77-81` ("the one state that must never exist"). Revisit when deciding whether run start refuses (a new `RunStartError` code) or the picker disables cardless decks; either is a behaviour change. Task 004's Superseded-since now records the gap.
2. **ADR 034 says `database_ops` "contains all SQL"; eight queries live in services and two routers use the session directly.** `app/services/deck_batch_edit.py:73,78,185,203`; `app/services/deck_practice_config.py:52,109`; `app/services/mastery.py:173,218`; `db.get` at `app/routers/api/field_def.py:98,118,137` and `app/routers/api/card.py:113`. The one-way dependency direction holds everywhere; only the "all SQL" clause is violated, and no guard test covers it. Revisit by amending ADR 034 to "ownership-scoped reads live in `database_ops`" or by moving the queries behind `db_*` functions with a source-scan guard.
3. **Four decisions the code makes that no ADR or Minor-decision entry records:** run-start ordering "unseen cards first, then ascending mastery" (`app/services/practice_run.py:182-185`); the declarative `BrowserRouter`/`Routes` mode rather than React Router's data router (`frontend/src/App.tsx:19-20`), which interacts with ADR 033 and ADR 024; bearer-token injection through `window.Clerk.session.getToken()` (`frontend/src/api/client.ts:5-26`); the constraint naming convention in `app/database.py:8-14` that Alembic autogenerate depends on. Decided in the same session: the router mode is ADR 053 and the naming convention is ADR 054 (which names a source-scan guard for the `alembic/env.py` import as needed); run-start ordering and token injection are left unrecorded for now.
