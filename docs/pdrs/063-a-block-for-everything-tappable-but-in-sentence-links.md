# PDR 063: A block for everything tappable but in-sentence links

## Status

Active

## Context

The app is used on phones held upright as well as on wide screens, and a user acts on it by tapping.

Drawn in thin lines and plain text on white, a row that opens a page and a line of text that only labels look alike until the user tries them.

Much of what a screen shows can be opened or acted on, such as a deck or an answer, and some of it is only read, such as a heading or a count.

A shape drawn with an edge and a shadow reads as an object standing off the page, and a shape drawn flat reads as part of the page.

A Flashy card holds one value for each field of its deck, often more than two.

PDR 054 makes white what sits on the page, and ink the color of outlines and shadows.

Some pages are read as text, one sentence after another, such as PDR 062's page that says what Flashy keeps about a person. A link inside such a sentence sits among words that cannot be tapped.

A block drawn around a few words inside a sentence breaks the sentence apart. Underlined words in a sentence are read across the web as a link.

PDR 020 drew everything that can be tapped as a block. This record replaces PDR 020 to draw a link inside a sentence as underlined words, and restates the rest unchanged.

## Decision

We will draw everything a user can open or act on, but a link inside a sentence, as a white block with rounded corners, a thin ink outline and a short solid ink shadow, so that what can be tapped looks like a thing.

We will draw a link inside a sentence as underlined words within it.

## Alternatives considered

### A white sheet with yellow highlighter swipes and pen marks

Rejected because its rows read as text until a user learns they are links.

### An index card with two faces

Rejected because it draws the two-sided flashcard that Flashy's cards, with their many fields, replace.

### Thin lines only

Rejected because what can be tapped looks like text.

### Thick purple outlines

Rejected because it reads as a common template rather than as Flashy.

### Raised panels drawn like keys

Rejected because panels that cannot be tapped look as if they can.

### A block around a link inside a sentence

Rejected because a block around a few words reads out of place in a page of text.

### A link inside a sentence drawn as plain words

Rejected because it reads as words that cannot be tapped, and the user copies it by hand.

## Consequences

**Positive**

- The user tells what they can tap from what they can only read by its outline and shadow.
- The user reads a sentence whole, with its link inside it.

**Negative**

- The user sees fewer things on one screen, since each block gives room to its edge and shadow.
- The user tells a link inside a sentence by its underline alone, without the outline and shadow of everything else that can be tapped.

**Neutral**

- The user sees each deck, card and practice as a thing of its own on the page.
